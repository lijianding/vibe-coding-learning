# 01 学习方法与 Vibe Coding 工作流

## 目标
理解“AI 写代码”和“可控的软件工程”之间的区别。

## 1. 正确流程

```text
业务需求
↓
需求规格
↓
数据模型
↓
权限设计
↓
开发计划
↓
AI 实现
↓
人工验收
↓
测试
↓
Git Diff
↓
Code Review
↓
Commit
```

## 2. 不要这样做
```text
帮我做一个完整 SaaS
```
问题：改动过大、难回滚、难测试、权限容易遗漏。

## 3. 推荐这样做
先让 AI：
- 阅读现有项目
- 不修改代码
- 输出实现计划
- 标明影响文件
- 标明数据库变化
- 标明权限影响
- 标明测试方案

再让 AI 只实现一个小功能。

## 4. 你的职责
AI 适合：
- 写代码
- 生成测试
- 重构
- 解释错误
- Review

你必须掌握：
- 需求
- 数据模型
- 权限
- 业务规则
- 验收
- 安全边界
- 上线决策

## 5. 每次改动后的固定检查
- 功能是否满足需求
- 是否破坏旧功能
- 是否存在越权
- 是否存在跨租户访问
- 是否处理异常
- lint/typecheck/test/build 是否通过
- git diff 是否合理

## 6. 练习
让 AI 只做“项目列表”计划，不允许写代码。

Prompt：
```text
请阅读现有项目，不修改任何代码。
我要新增“项目列表”功能。
请输出：
1. 需求拆解
2. 数据来源
3. 页面结构
4. 权限要求
5. 需要修改的文件
6. 测试方案
7. 潜在风险
```

## 验收
能解释为什么“能跑”不等于“可上线”。
